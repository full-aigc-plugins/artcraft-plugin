# ArtCraft — quality-review

## Purpose

本能力定义 ArtCraft 在 quality-review 范围内对用户、宿主与下游系统承诺的可观察行为、失败语义和验收证据，确保规划、执行与实际交付之间保持可验证的边界。当前为目标规范，尚未实现。

## ADDED Requirements

### Requirement: AC-QA-001 技术与创作证据分离

质量结果 SHALL 分别记录工程、技术、创作和接受状态；证据绑定文件摘要及运行身份，NOT_RUN 不得当作 PASS，视觉评分不得覆盖技术失败。

#### Scenario: AC-QA-001-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成技术与创作证据分离并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-QA-001-N 边界条件

- **WHEN** 视觉评价较高但成片无法解码
- **THEN** 技术门禁失败，不标记任务完成

#### Scenario: AC-QA-001-RECORD 当前交付绑定的独立审阅记录

- **WHEN** 单独安装的 artcraft-cli-review 技能收到交付包回执摘要、当前资产版本和具名评价者的观察文件
- **THEN** 系统先通过公开验包入口核对当前交付，再保存包外审阅记录及观察证据，不修改交付包或任务账本
- **AND** 工程完整性、技术、创作与接受状态分别记录，缺项或 NOT_RUN 保持待审；任何技术或创作失败阻止接受结论
- **AND** 观察绑定子节点、责任插件、资产 ID、版本、摘要及适用的对象、帧或区域；品牌参考同样绑定当前包内资产
- **AND** 旧包摘要、旧资产版本、无证据的 PASS、非人工接受声明、篡改观察文件或报告摘要在保存或重新核验时被拒绝
- **AND** 记录的评价者声明不冒充自动视觉验证，不将账本任务提升为 completed

### Requirement: AC-QA-002 受限局部修订

质量循环 SHALL 将问题绑定对象、帧或区域及责任插件；设置最大轮数、预算与停滞规则；目标变化使旧验收与授权失效。

#### Scenario: AC-QA-002-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成受限局部修订并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-QA-002-N 边界条件

- **WHEN** 连续修订无改善或达到预算
- **THEN** 停止自动修订，保留最佳可验证版本并报告未解决问题

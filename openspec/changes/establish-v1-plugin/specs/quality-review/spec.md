# ArtCraft — quality-review

## Purpose

本能力定义 ArtCraft 在 quality-review 范围内对用户、宿主与下游系统承诺的可观察行为、失败语义和验收证据，确保规划、执行与实际交付之间保持可验证的边界。当前为目标规范；独立审阅记录与明确补丁返工已有受限证据，完整创作验收仍未完成，具体范围以 project-status.json 和 docs/evidence/ 为准。

## ADDED Requirements

### Requirement: AC-QA-002 受限局部修订

质量循环 SHALL 将问题绑定对象、帧或区域及责任插件；设置最大轮数、预算与停滞规则；目标变化使旧验收与授权失效。

#### Scenario: AC-QA-002-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成受限局部修订并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-QA-002-N 边界条件

- **WHEN** 连续修订无改善或达到预算
- **THEN** 停止自动修订，保留最佳可验证版本并报告未解决问题

#### Scenario: AC-QA-002-STEP 当前审阅驱动的持久化修订步骤

- **WHEN** 独立技能收到可信交付与审阅回执、冻结目标及授权的修订策略，以及针对责任节点的明确命令补丁
- **THEN** 协调器先验证当前版本，限制修改到失败节点及传递依赖，要求原生源工程绑定并保留旧交付，执行后自动打包新版本
- **AND** 每个步骤持久化轮次和审阅失败检查数量；达到策略轮数、共享预算或声明的停滞阈值时停止，并保留最佳可核验包及未解决问题
- **AND** 改变目标、策略或授权不能沿用旧循环；待审缺项不触发新修订，任何已停止循环不自动重启
- **AND** 重复步骤复用已保存结果；超时或缺失执行回执记为 outcome_unknown，在显式恢复同一步骤前不提交新的原生修改
- **AND** 该入口不自动生成补丁、不执行模型评价、不伪造人工接受；审阅声明和完整创作验收仍独立记录

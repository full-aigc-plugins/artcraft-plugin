# ArtCraft — task-execution

## Purpose

本能力定义 ArtCraft 在 task-execution 范围内对用户、宿主与下游系统承诺的可观察行为、失败语义和验收证据，确保规划、执行与实际交付之间保持可验证的边界。本文件是规格事实源；当前已实现范围与未完成验收以 tasks.md 和 project-status.json 的证据映射为准。

## ADDED Requirements

### Requirement: AC-TX-001 版本绑定与单写

执行 SHALL 绑定 planHash、inputHashes、projectRevision、runtimeIdentity 和有效授权范围；同一工程只有一个写入者，冲突不得覆盖用户修改。

#### Scenario: AC-TX-001-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成版本绑定与单写并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-TX-001-N 边界条件

- **WHEN** 用户在 GUI 中修改工程后提交旧计划
- **THEN** 返回 revision_conflict 并重新检查工程，不覆盖新修改

#### Scenario: 通过公开技能接口修订登记的原生工程
- **GIVEN** 输入素材协议登记了旧交付的原生工程引用、manifest 及文件摘要
- **WHEN** 四个领域节点声明 `sourceProject.assetId` 和匹配的 `expectedRevision`
- **THEN** ArtCraft 从登记输入解析源交付，核验全部 manifest 文件并通过公开 `--source` 接口另存修订；禁止任意源路径和重建 document
- **AND** 准备执行与验收时重新核验源交付，源摘要漂移拒绝执行或拒绝交付；输出记录源工程摘要、输入血缘和继承素材，旧交付保持不变


#### Scenario: AC-TX-001-META 冻结修订冲突保留项目元数据

- **WHEN** 已冻结的工作流修订因计划、授权或实际运行时登记绑定改变而被拒绝
- **THEN** 公开入口 SHALL 保留原安装回执、登记表、冻结计划和执行结果，不在绑定校验前写入新项目登记材料，也不启动原生编辑
- **AND** 固定制品的隔离缓存安装可用于核对实际身份，但不得因此把被拒绝的请求发布为原项目当前安装身份

#### Scenario: AC-TX-001-CACHE 历史复用绑定同一授权范围

- **WHEN** 新修订寻找可复用的历史节点结果
- **THEN** 工作流所有者、逻辑项目、节点指纹、历史工作流授权及原生产任务授权 SHALL 同时匹配当前请求；不得将旧授权任务作为新授权范围下的已执行结果
- **AND** 同一授权范围内未受影响节点继续复用原任务，新授权范围按当前有效授权登记并核验自己的任务；历史错误复用记录不能绕过原任务授权核对

### Requirement: AC-TX-002 幂等与不明确结果恢复

任务 SHALL 在副作用前登记幂等键；超时且执行结果未知时进入 reconciling；核对原任务或产物前不得重新提交。

#### Scenario: AC-TX-002-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成幂等与不明确结果恢复并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-TX-002-N 边界条件

- **WHEN** 提交后断线且无法确定是否执行
- **THEN** 保存任务身份并核对已有结果，不增加重复写入或付费提交

#### Scenario: 独立监督与崩溃接管

- **WHEN** 调度器在原生子任务运行时异常退出
- **THEN** 已启动的独立监督 worker 继续观察同一子任务的 close、取消与截止时间，并以原任务 token、epoch 和命令摘要记录停止证据
- **AND** 再次执行同一冻结工作流仅接管已有停止证据并重新核验产物；不启动第二次原生操作、不再次分配预算
- **AND** 原生进程未确认停止、worker 也已崩溃或副作用提交窗口结果不明确时保留写占用和等待状态；PID 消失和产物存在不能代替停止证据

#### Scenario: 验收阶段中断与并发接管

- **WHEN** 进程在技术核验过程中退出，或两个恢复调用核对同一已停止任务
- **THEN** 允许重新核验同一 token 和 epoch 的产物，至多发布一个结果且保留原 attemptId
- **AND** 授权失败、命令身份变化或产物损坏不能发布技术就绪；取消必须在停止证据之后收敛

#### Scenario: AC-TX-002-DIAG 已停止子任务失败诊断

- **WHEN** 原生子任务非零退出且监督器确认进程组停止
- **THEN** 同一 token 与 epoch 的停止记录 SHALL 保留输出字节数、SHA256、有界采集完整性和受支持的结构化领域错误码；任务状态与工作流失败节点可查询该诊断
- **AND** 不持久化原始输出文本；未知、超限或非结构化错误不猜测领域原因；再次查询和恢复不重新执行子任务，旧停止记录仍可读取
- **AND** 输出采集不能阻塞取消、进程组核对或产生无限内存增长，诊断本身不能代替停止证据

#### Scenario: AC-TX-002-AUDIO 必需源音轨缺失

- **WHEN** FilmCraft 在要求音频的成片任务中报告结构化 `export_audio_missing` 并非零退出，且监督器确认进程组停止
- **THEN** 失败记录 SHALL 保留该领域错误码与输出摘要，不能把自动生成的静音 AAC 当作源音轨成功证据
- **AND** 依赖该成片的后续节点不得执行；失败目录中的原生工程、音轨检查和导出探测应保留供诊断
- **AND** 重复执行同一冻结计划保留原任务、尝试与诊断，不重复原生操作或预算分配

### Requirement: AC-TX-003 取消与预算边界

任务 SHALL 区分 cancel_requested 与 cancelled；父子调用共享预算和截止时间；只允许一个层级负责同一副作用的重试。

#### Scenario: AC-TX-003-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成取消与预算边界并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-TX-003-N 边界条件

- **WHEN** 父任务取消但子渲染仍在运行
- **THEN** 保留占用并停止新依赖调度，确认停止后才标记 cancelled

#### Scenario: AC-TX-003-B 父子共享预算且并发不能超支

- **WHEN** 同一 owner、workflowId 与 authorizationRef 下的多个节点并发申请执行额度
- **THEN** 在同一个 SQLite 写事务中核对共同上限并登记每个任务的占用；额度不足的节点在原生副作用之前停止
- **AND** 消耗上界由可信适配器提供，缺失、负数、非安全整数与溢出不能视为免费；模型 payload 不能自行指定消耗

#### Scenario: AC-TX-003-R 修订、重开与未知结果

- **WHEN** 同一工作流授权范围重跑、登记新的计划修订或遇到执行结果不明确
- **THEN** 同修订与同任务不重复占用额度，首个计划不计修订轮次，之后每个新计划修订占用一次 maxRevisions
- **AND** 授权范围内预算政策固定；未知或失败的执行额度保守保留，不因断线、进程消失或新计划版本而重置
- **AND** 历史账本没有预算证据时保留状态读取，但拒绝在同一旧授权范围内凭空补记免费历史

#### Scenario: AC-TX-003-PROBE 取消后的存在性权限竞态

- **WHEN** 已观察原生 close，但进程组存在性探测返回 EPERM
- **THEN** 监督器 SHALL 保守视作进程组可能存在并继续有界观察，不立即放弃后续停止探测，不把权限不足当作组已停止
- **AND** 只有绑定原任务的 close 及可信进程组停止证据允许释放占用；持续 EPERM、其他探测错误或发信号失败仍保留未知状态；恢复不重放原生任务或重复分配预算

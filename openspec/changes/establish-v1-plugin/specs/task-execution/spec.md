# ArtCraft — task-execution

## Purpose

本能力定义 ArtCraft 在 task-execution 范围内对用户、宿主与下游系统承诺的可观察行为、失败语义和验收证据，确保规划、执行与实际交付之间保持可验证的边界。本文件是规格事实源；当前已实现范围与未完成验收以 tasks.md 和 project-status.json 的证据映射为准。

## ADDED Requirements

### Requirement: AC-TX-002 幂等与不明确结果恢复

任务 SHALL 在副作用前登记幂等键；超时且执行结果未知时进入 reconciling；核对原任务或产物前不得重新提交。

#### Scenario: AC-TX-002-P 合同条件满足

- **WHEN** 请求满足本需求的来源、输入、状态和证据条件
- **THEN** 系统按本需求完成幂等与不明确结果恢复并返回可核对的结果
- **AND** 结果绑定当前版本与执行身份，不提升未验证能力状态

#### Scenario: AC-TX-002-N 边界条件

- **WHEN** 提交后断线且无法确定是否执行
- **THEN** 保存任务身份并核对已有结果，不增加重复写入或付费提交

#### Scenario: 独立监督与崩溃接管

- **WHEN** 调度器在原生子任务运行时异常退出
- **THEN** 已启动的独立监督 worker 继续观察同一子任务的 close、取消与截止时间，并以原任务 token、epoch 和命令摘要记录停止证据
- **AND** 再次执行同一冻结工作流仅接管已有停止证据并重新核验产物；不启动第二次原生操作、不再次分配预算
- **AND** 原生进程未确认停止、worker 也已崩溃或副作用提交窗口结果不明确时保留写占用和等待状态；PID 消失和产物存在不能代替停止证据

#### Scenario: AC-TX-002-RECEIPT 非零工作流结构化回执

- **WHEN** 公开Python工作流入口收到固定运行时返回的非零工作流结果，例如waiting、blocked或failed
- **THEN** 非零退出与既有error字符串保持兼容，同时返回对象类型workflowReceipt，内容与原运行时回执及项目结果记录一致，调用方无需解码error字符串即可读取state、runKey及节点状态
- **AND** 普通安装／输入异常不得伪造workflowReceipt；结构化等待回执不授权重放、释放写占用或发布技术就绪

#### Scenario: AC-TX-002-WORKER 原生产物存在但监督证据缺失

- **WHEN** 独立监督 worker 在原生进程启动后崩溃，且没有原 token、epoch 和命令摘要绑定的可信停止记录
- **THEN** 同一冻结工作流及重复恢复 SHALL 保留原 attempt、预算和写占用，返回等待结果且不得第二次启动原生任务
- **AND** 测试或用户观察到原生进程组消失、原工程或导出文件存在，不能被自动提升为账本停止证据或技术就绪；原文件保留供核对

#### Scenario: 验收阶段中断与并发接管

- **WHEN** 进程在技术核验过程中退出，或两个恢复调用核对同一已停止任务
- **THEN** 允许重新核验同一 token 和 epoch 的产物，至多发布一个结果且保留原 attemptId
- **AND** 授权失败、命令身份变化或产物损坏不能发布技术就绪；取消必须在停止证据之后收敛

#### Scenario: AC-TX-002-DIAG 已停止子任务失败诊断

- **WHEN** 原生子任务非零退出且监督器确认进程组停止
- **THEN** 同一 token 与 epoch 的停止记录 SHALL 保留输出字节数、SHA256、有界采集完整性和受支持的结构化领域错误码；任务状态与工作流失败节点可查询该诊断
- **AND** 不持久化原始输出文本；未知、超限或非结构化错误不猜测领域原因；再次查询和恢复不重新执行子任务，旧停止记录仍可读取
- **AND** 输出采集不能阻塞取消、进程组核对或产生无限内存增长，诊断本身不能代替停止证据

#### Scenario: AC-TX-002-AUDIO 必需源音轨缺失

- **WHEN** FilmCraft 在要求音频的成片任务中报告结构化 `export_audio_missing` 并非零退出，且监督器确认进程组停止
- **THEN** 失败记录 SHALL 保留该领域错误码与输出摘要，不能把自动生成的静音 AAC 当作源音轨成功证据
- **AND** 依赖该成片的后续节点不得执行；失败目录中的原生工程、音轨检查和导出探测应保留供诊断
- **AND** 重复执行同一冻结计划保留原任务、尝试与诊断，不重复原生操作或预算分配

#### Scenario: AC-TX-002-MAPPING 效果参数拒绝的混合任务诊断

- **WHEN** 固定 EffectCraft 技能源在真实子进程中因未知效果或蒙版字段返回 unsupported_mapping，并且同一 token／epoch 的任务停止已被确认
- **THEN** 失败任务、工作流节点及后续状态查询保留精确领域错误码与输出摘要，不保存原生诊断正文
- **AND** 依赖失败节点的下游不执行；原先成功的上游原生交付保持不变
- **AND** 重复同一冻结计划复用失败尝试、诊断与预算，不重放原生操作
- **AND** 修正参数后的新修订可复用未受影响节点并完成混合交付与打包
- **AND** 相似后缀、额外 JSON 字段、非结构化输出和冲突错误仍不能变成该领域错误码
